### 5.3 Lobby and join-code flow

Create: `client.create("party", { name, build, deviceId })`. `onCreate` draws a 5-char code from the unambiguous alphabet, checks uniqueness with `presence.sadd("wdi:codes")`, sets `this.roomId = code`, `setMatchmaking({ private: true })`, `maxClients = 10`. Join: `client.joinById(code.toUpperCase(), opts)`. Every joinById failure (missing, locked, full, version mismatch) returns one generic "party not found or unavailable"; specific codes exist only inside a room. Released codes keep a 30-minute presence TTL before reuse. The matchmake route sits behind `trust proxy` with a per-forwarded-IP token bucket (30/min, burst 10) and a global cap (300 joinById/min). Start: at least 1 human, phase lobby, leader only; when `players.size` is below `balance.players.min` the room adds NPC seats up to it before dealing, and the leader may add NPC seats up to `players.max` (GDD 3.12). Which seats are NPCs is kept in room memory only (`sim/Npc.ts`, a `Set<string>` that lives as long as the room): an NPC is an ordinary `Player` on the wire, with a session-shaped id (`generateId()`), a name from the server-only NPC name pool (`pickNpcNames`), never the leader; humans are counted by connection, never by the `connected` flag alone (A41). `lobby.addNpc` / `lobby.removeNpc` / `lobby.settings` are leader-only lobby commands consumed in the step; a human joining a full party takes the newest NPC seat in `onJoin`. Ready is advisory. Kick, transfer and leader handoff ship in M7; a kicked device is banned by `deviceId` + name for that room.

### 5.4 State schema and role secrecy

Schema 5 builder style, no decorators, every Schema under 63 fields, four privacy classes:

```ts
// packages/shared/src/schema/index.ts (excerpt)
export const Presence = schema({ x: t.int16(), y: t.int16(), z: t.int8(), yaw: t.float32(),
  animId: t.uint8(), statusBits: t.uint16(), transitUntilTick: t.uint32() }, "Presence");
export const Private = schema({ role: Role, inventory: Inventory, notebook: t.array(NotebookEntry),
  tasks: t.array(TaskEntry), cabalMates: t.array('string'), cooldownEndTick: t.map('uint32'),
  ledger: t.array(LedgerLine), lensCharges: t.uint8(), myVote: t.string() }, "Private");
export const Player = schema({
  id: t.string(), name: t.string(), traits: Traits, alive: t.boolean(), connected: t.boolean(),
  ready: t.boolean(), hasVoted: t.boolean(), sceneId: t.uint8(),          // Public roster
  presence: t.ref(Presence).view(),                                      // SceneScoped (V1) / Proximity (V1.5)
  priv: t.ref(Private).view(),                                           // Own client only
}, "Player");
export const Door = schema({ id: t.string(), state: t.uint8() /*0 open 1 closed 2 locked 3 broken*/, swingUntilTick: t.uint32() }, "Door");
export const SceneState = schema({ doors: t.map(Door), spots: t.map(Spot), bodies: t.map(Body), clues: t.map(Clue), props: t.map(Prop) }, "SceneState");
export const GameState = schema({ schemaVersion: t.uint8(), phase: t.uint8(), phaseEndsTick: t.uint32(), tick: t.uint32(),
  round: t.uint8(), leaderId: t.string(), settings: Settings, taskBar: t.uint8(),
  players: t.map(Player), scenes: t.map(SceneState).view(), meeting: MeetingState, winner: t.uint8() }, "GameState");
```

`Settings` also carries `npcDifficulty: uint8` (0 easy, 1 normal, 2 hard; GDD 3.12) and `npcSeats: uint8`, how many seats are NPCs, a count that never says which: the marker is the `Set<string>` of `sim/Npc.ts` room memory, written into the match log (`players[].isNpc`) and nowhere else (A41). `onJoin` sets `client.view = new StateView()` and adds the player's own `Player` with its `presence` and `priv` tags and the `SceneState` of its scene. Others are never sent as players: each placed seat walks as an `Avatar` in `SceneState.avatars` (a `.view()` map whose entries `Visibility.ts` adds one by one), keyed by a random 6-byte handle that is re-rolled on every scene entry and every death, and when an impersonation applies or drops, which happens only with no other living seat in the scene, inside a scene entry, or at a Knife strike. An avatar carries the seat whose name, look, scarf and hat glyph it shows (`lookOf`), the height it is drawn at, and the presence fields; its true `seat` is tagged for ghosts only, and a seat aiming its Last Shot receives no avatar. `Player.look` is the public look (GDD 3.17), written for every seat in one tick when the role card closes; `Private.sceneId` replaces the public scene index (until 5F's contract phase, the public `Player.sceneId` and other seats' `presence` are still written beside them, A50). No field marks a cover or an impersonation. Kill and Bandage name a handle that the server resolves to a seat; list acts name a seat. Role, inventory, notebook, cooldowns, cover picks and the handle-to-seat map are therefore never on the wire for other living clients. Every match stream is `sfc32` with four crypto seed words (`sim/seeds.ts`). In V1.5 (dark scenes first, M5b) `Visibility.ts` adds and removes avatars by radius + occluder raycast at 5-10 Hz with a +1 tile hysteresis, so a sprite has history before it is visible. `animId` uses one shared `swing` id for Kill, Crowbar and Check so the animation never discriminates. Fingerprint toucher logs, Blood timers and Case Board intersections stay in room memory. `Player.alive` is public but a kill does not flip it: the server keeps `PlayerSim.dead` in room memory, tells the victim with the private `killed`, and flips `alive` for every dead player when the next meeting opens (or at the ejection), so an unreported kill is known only to its victim and to whoever finds the body (GDD 3.7, A30). A dead viewer's view receives every avatar in its scene, with its true seat; a living viewer's never receives a dead player's. Votes are stored in `priv.myVote`; only `hasVoted` is public; the tally is published in `voteResult`. The meeting phase, board rows and missing list are in `MeetingState` so a reconnecting client rebuilds the UI from state. A fuzz test diffs the state a non-Cabal bot receives over a scripted kill and asserts no field change correlates uniquely with the killer.

| S->C | `vfx`, `shot` | `{sceneId, x, y, kind}` (a Knife strike's disguise puff only, to the scene) / `{fromId, targetId, role}` (only during a reveal: an ejected Gamekeeper's shot) | |

**`roleReveal` payload (final, M1).** `{roleId, team: "village"|"cabal"|"neutral", goal, abilities: [{id, name, key, cooldown: number, uses: number | null}], inventory: [{defId, name, qty, tooltip}], cardText, beware, teammates: [{id, name}], traits: {height: "short"|"mid"|"tall", scarf: "red"|"green"|"blue", hat: "cap"|"bowler"|"bare"}}`. Trait values are the ids of `traits.json` (the same order as the public `Player.traits` indices); `teammates` lists the other members of a faction whose `membersKnowEachOther` is true (the Cabal) and is empty for everyone else; `uses` is `usesPerMatch` or null; `cooldown` is seconds, and Kill's is the cooldown of the party size; abilities gated by `minPlayers` above the party size are omitted. The payload is built from `roles.json`, `abilities.json` and `items.json` by `buildRoleReveal` on the server. Round 5 adds four optional main-mode fields: `deck` (the match's deck, card role ids in deck order), `look` (the look this seat walks as), `portrait` (its card portrait key) and, for cover roles only, `coverHints` (GDD 3.17). `docs/PROTOCOL.md` carries the full, generated message tables.

**Start flow (M1).** `lobby.start` is queued like every message and consumed in the room's fixed step (`runLobbyCommands`, `rooms/handlers/lobby.ts`). It creates the match's independent random streams (`sim/seeds.ts`: `sfc32`, four `crypto.randomInt` words per stream, A50), calls `dealMainDeck` (`sim/Deck.ts`: `dealDeck` over `deckFor(n).cards` on the `deal` stream, every Killer card dealt, two cards left undealt) and `dealTraits` on the `traits` stream, writes `priv.role`, `priv.inventory`, `priv.cabalMates` and the public `traits`, locks the room, sets `phase = roleReveal` with `phaseEndsTick` from `balance.json` `phases.roleRevealS`, and sends each client its own `roleReveal`. When every living, connected player is Ready or the card time elapses the phase becomes `grace` (`phases.graceS`) and each client gets `sceneEnter {sceneId: "overworld", spawn, facing}` with its seat's `square_N` spawn (the first overworld spawn if the scene has none). Below `players.min` seats `startMatch` first adds NPC seats up to it (names from the `npcNames` stream of `sim/seeds.ts`), so every deck row is dealt in full; the NPC brain (`runNpcs`, after `syncRoster` and before `applyInputs`, `sim/npc/*`) readies each NPC seat on the role card after an `npc.ready` delay, then runs its routine (stations, strolls, idling, reactions), reports and votes, each NPC seat drawing only from its own keyed streams `npcPlay:<seatId>` and `npcTiming:<seatId>` (GDD 3.12, A41 and A50).

Error codes: 422 cannot, 423 locked, 424 cooldown, 425 wrong phase, 426 busy, 427 out of range, 428 closed (profile). `docs/PROTOCOL.md` is generated from `@wdi/shared/protocol`.

### 5.6 Movement, actions and netcode

```ts
// apps/server/src/sim/Step.ts — fixed order inside setFixedTimestep(step, 20); PartyRoom drains the lobby
// queue and runs the lobby phase timers right after step() (rooms/handlers/lobby.ts)
export function step(room: PartyRoom, ctx: StepContext) {
  room.state.tick++;
  runDebugStart(room);        // WDI_DEBUG=1 only: a debug.play flag raised in a callback, consumed here
  syncRoster(room);           // one PlayerSim per seat; placeNewPlayers spreads newcomers on square_<n> once the phase is a world phase and sends their one sceneEnter
  applyInputs(room);          // exactly one input per client, newest wins, server-normalised, speed table by sprint/sneak/wounded
  moveAndCollide(room);       // swept AABB vs nav bitmap; 250 ms position ring per player
  runCommands(room);          // queued act.* in arrival order: kill, interact, hold, hide/check, present
  runPortals(room);           // synchronous; sets busy/transit, clears inputs, bumps lastInputSeq
  runAiAndHazards(room);      // sim/Clues.ts runDecay: clue decay and the per-scene cap (M3); wolves (M5)
  if (room.state.tick % 4 === 0 || sim.viewsDirty) reconcileViews(room);   // Visibility.ts at 5 Hz, at once after a crossing or placement
  runPhases(room);            // sim/Phases.ts: phase timers, meeting requests, deaths -> checkWin, game over (M3)
}
```

Every C->S action is queued and consumed inside `step()`; nothing mutates state in a message callback. Players have a `busy` state (dying, transit, hidden, channelling) during which actions on or by them are rejected with 426. Kills resolve on the validated tick (the 1 s animation is cosmetic) with range slack of `range + maxSpeed * 0.25 s` against the position ring, same scene, alive, not hidden, not bandaged, and a nav raycast. Held actions are start/stop commands re-validated every tick. `Presence.animId` is `interact` while the seat's own `act.hold` runs, `walk` only on a tick its position actually changed, else `idle` (`publishPresence`). `patchRate` 50 ms; the client lerps remote players with a 150 ms delay and teleports a sprite on view add. No client prediction in V1 (lerp only; the local player moves on server echo with input-rate smoothing). Positions are `int16` pixels, enums `uint8`, time is the tick counter. The swarm bot publishes tick-time and patch-size histograms through `/health`; M4 is gated on p95 tick < 15 ms with 10 bots and 3 wolves.

**M2 implementation notes (Session G).** These are implementation constants, not rules; they live in `apps/server/src/sim/constants.ts` and `packages/shared/src/nav` and are listed here until the owner moves any of them into `balance.json`: the collision box is a 0.5-tile square under the feet (`FOOT_HALF_PX` 16); a client whose input goes quiet stops after 5 ticks; a door is usable from 1.5 tiles (`PORTAL_REACH_TILES`, the same reach as the other verbs); the ring holds 250 ms (6 samples). Speeds, the 0.6 s transit, the 3 s swing and door noise come from `balance.json`. `input.move` keeps only the newest message per client in the queue; `act.enterPortal` is queued by `runCommands` and consumed by `runPortals` (errors come back as the `error` message, success as `sceneEnter`, not as a request/response). `Player.presence` and `Player.priv` carry their own view tags (1 and 2) so a client can be granted another player's `presence` without receiving even an empty `priv`; `Visibility.ts` adds and removes that tag as players enter and leave a client's scene. Presence is encoded to other clients only in world phases (grace, day, dusk, night, dawn, immunity, final night). The first placement in a world phase puts every player on `square_<n>`, sets `alive`, fixes the scene profile from the party size and sends `sceneEnter`. `WDI_DEBUG=1` adds `debug.play`, which moves a lobby to grace for the bot soak and the tests.

**M3 implementation notes (Session L).** `runCommands` dispatches `act.ability`, `act.hold`, `act.reportBody` and `act.bell` to `sim/Actions.ts` (Kill in `Kill.ts`, Collect in `Hold.ts`) and ends by running `runHolds`, so every hold is re-validated each tick. `validateKill` and `segmentBlocked` (pure, `packages/shared/src/rules/kill.ts`) decide a strike; the room only reads state, calls them and writes the result. "Alive" in a verb always means `!PlayerSim.dead`. Clue memory (decay tick, spawn order, collectors) lives in `RoomSim.clueMeta`; the schema carries only what a client may read. `runDecay` (Clues.ts) expires Footprints; the per-scene cap is applied at each spawn. Ghosts skip collision (they stop at the scene edge), skip the busy and lock checks of portals, swing no door and emit no noise; a ghost's crossing moves only `PlayerSim.sceneIdx`. `emitNoise` lives in `sim/Noise.ts`.

### 5.7 Scene sync

`act.enterPortal` validates distance, lock state, profile and phase, sets `sceneId`, position and the 0.6 s transit, swaps `scenes` view entries and other players' `presence`, and broadcasts a door `swing` plus a noise event. The client `World` scene restarts with the new `sceneId` and loads only that scene's manifest. Meetings run the same transition path for every player (busy, input clear, `sceneEnter` to a spread spawn). After a meeting everyone stays at the square; hiding spots are emptied; bodies stay. Ghosts bypass portal checks and get an all-scenes view flag.

**M3 meeting flow (Session K, A31).** `runPhases` (`sim/Phases.ts`, last in the step) owns the phase clock, the drain of `sim.deaths` and `sim.meetingRequests`, and the debug helpers; `sim/Meeting.ts` opens the meeting, takes votes and runs the reveal; `sim/Win.ts` evaluates `checkWin`, ends the match and returns the room to the lobby; `sim/Chat.ts` routes chat by channel; `sim/Flow.ts` holds `setPhase` and the room-memory flow state. A meeting places every player on the square without a `sceneEnter` and sends `meetingStart` afterwards; immunity places them again with an announced `sceneEnter`, which is the client's cue to leave the meeting. A living viewer's reconcile skips ghosts (`PlayerSim.dead`); in the meeting, reveal and game-over phases `isWorldPhase` is false and no presence is encoded.

### 5.8 Rules engine

`packages/shared/src/rules`: pure functions with seeded PRNGs (`mulberry32`, and `sfc32` for the match streams of `sim/seeds.ts` since round 5) and tick-based time: `dealDeck(ids, cards, alwaysDealt, rng)` deals the public deck (`roles.json` `decks[String(n)].cards`); `dealTraits`; `validateKill(actor, target, scene, tick)`; `generateClues(kill, sceneGraph, rng)` (2 of 3 traits, print, Blood, smear); `resolveVotes(votes, alive, suspectSet, consecutiveNoEject)`; `intersectSuspects(verified, living)`; `checkWin(state)` (parity with Thief/Drifter exceptions, practice rule, tasks, Final Night); `rollCall(state)`. Property tests cover every deck row (every Killer dealt, two cards undealt, seed reproducibility). The room only orchestrates: read state, call rule, write state. (M3: `resolveVotes(votes, living, options)` and `checkWin(livingFactions, rule)` are the two shipped signatures; the anti-stall rules are options that default off and the suspect set, the practice-rule exceptions and the Final Night arrive with M4.)

### 5.9 Client

Scenes: `Boot` (flags, `/health` poll) -> `Preload` -> `Landing` (DOM) -> `Lobby` (DOM) -> `RoleReveal` (DOM, CSS flip) -> `World` (restart per `sceneId`, camera follow with bounds and 0.1 lerp) -> `Meeting` (launched over a sleeping `World`) -> `GameOver`. HUD, inventory, notebook, chat, board and touch controls are a DOM overlay with `pointer-events: none` except on controls; Phaser draws world prompts and nameplates. `NetworkService` wraps `@colyseus/sdk` with `Callbacks.get(room)`, typed `send` / `request`, a `mitt` bus, and the reconnection token in `localStorage` keyed by room code (cleared on consented leave or game over). `EntityView` maps players and scene entities to sprites; `PlayerView` composes body + scarf + hat + blood overlays and picks `char/<body>/<anim>/<dir>` keys; a shared `dirFromVector(dx, dy)` in `@wdi/shared` with a unit test is the only direction table. Input is timer-driven at 20 Hz, decoupled from rAF, coalesced after `visibilitychange`.

Scene flow (round 3): `NetworkService.room` (getter, plus a `room` bus event, `null` once the room is gone) is what `net/worldRouter.ts` attaches its two feeds from, `ColyseusWorldFeed` and `ColyseusMeetingFeed` (`net/meeting.ts` is the contract: public roster, `MeetingState`, the clock, own vote, chat lines, the `meetingStart`, `voteResult`, `gameOver`, `chat.msg` and `phaseChange` events, `vote(target)` and `say(text)`). The world feed registers the room's `sceneEnter` once and the router re-emits it on `net.bus` for `RoleReveal`. The router is the only code that starts, sleeps or stops `World`, `Meeting` and `GameOver`: a `sceneEnter` while no meeting is open restarts `World`; `meetingStart` sleeps `World` and starts `Meeting`; only a `sceneEnter` that arrives after `meetingStart` stops `Meeting` and starts `World`; `gameOver` stops both and starts `GameOver`; a `phaseChange` back to the lobby starts `Lobby`. `?mock=1` has the same shape: `MockNetwork.openMeeting` runs a `MockMeetingFeed` (`net/mock/meetingMock.ts`) when the mock world sends `meetingRequest`, then calls the world feed's `resume()` or ends the match.

### 5.10 Deployment

- The server bundles `@wdi/shared` and `@wdi/content` from source with tsup (both are devDependencies resolved with the `development` export condition), so `node build/index.js` needs no workspace package at runtime (A28).
- `ci.yml` (push / PR): checkout@v7, setup-node@v7 (22), pnpm via corepack, `pnpm lint && pnpm typecheck && pnpm test`, a dist size report.
- `pages.yml` (main): build the client and its workspace dependencies (`pnpm --filter "@wdi/client..." build`, since the production build resolves `@wdi/content` to its `dist`) with the server URL from `apps/client/.env.production` (an Actions variable `VITE_SERVER_URL` overrides it) and `VITE_BUILD_VERSION=${GITHUB_SHA::8}`, configure-pages@v6, upload-pages-artifact@v5 (`apps/client/dist`), deploy-pages@v5; Pages source = GitHub Actions; `base: '/Who-Did-It/'`; hash routing.
- **Server host, two steps (owner decision 2026-10-10).** M0 to M3: **Render Free** web service built from the GitHub repo (same build and start commands), accepting the 15-minute idle spin-down and the one-minute wake; the landing page polls `/health` and shows "Waking the village..." until the server answers. From the first playtest with friends (M3 exit): **Railway Hobby ($5/month, always-on, managed wss)** through Railway's GitHub integration; `railway.json` at the root carries the build (`pnpm install --frozen-lockfile --prod=false && pnpm --filter @wdi/server build`: the server's bundler and the two workspace packages are devDependencies, and a `NODE_ENV=production` variable would otherwise make the install skip them) and the start (`node apps/server/build/index.js`) with `/health` as the health check, so nothing is typed into the Railway UI; the server reads only `PORT` and `WDI_DEBUG`, which stays unset. Only `VITE_SERVER_URL` changes on the client side. No Dockerfile, no deploy workflow, no staging server, no PR previews. Single process; no Redis.
- `GET /health` -> `{ok, build, rooms, tickP95, patchBytes}`. CORS restricted to `https://groot99-droid.github.io` and localhost. The client pings every 20 s. `BUILD_VERSION` from `@wdi/shared/version.ts` is injected on both sides (the server takes `BUILD_VERSION`, else the first 8 characters of the host's commit variable, `RAILWAY_GIT_COMMIT_SHA` or `RENDER_GIT_COMMIT`; the client takes `VITE_BUILD_VERSION`, the same 8 characters in `pages.yml`); mismatches are refused with the generic join error and the client shows "refresh to update".

### 5.11 Security

Every action validated server-side (range, phase, cooldown, ownership, alive, busy). `maxMessagesPerSecond = 100` as a hard cap; per-type token buckets drop rather than disconnect; disconnect only after 3 overflows in 10 s. Names 2-16 characters, server-side profanity list (M7). Chat channels derived from alive status and role; the client's channel field is ignored. Debug handlers register only with `WDI_DEBUG=1` and never in production; a CI test asserts `debug.roles` is absent from a production build. Seeds sent to clients drive cosmetics only. `onLeave` during play spawns a "vanished" body; in lobby it frees the seat.

### 5.12 Testing

Vitest (shared): property tests for roles, traits, votes, suspects, win checks, `dirFromVector`. `@colyseus/testing`: 10 bots join; each sees its own `priv` and nobody else's; a bot in the tavern receives no `presence` for a player in the overworld; start -> `phaseChange`; portal updates `sceneId` and view contents; vote -> `voteResult` with no tally before reveal; drop / reconnect keeps seat and notebook; 11th join and version mismatch refused; 1,000 joinById calls from one IP are throttled; Blood state absent from the meeting roster. Playwright: two contexts create / join / start and both see a role card. Bots (`tools/bots`, M3): one brain in `walk.ts` serves the lobby swarm, the walkers and the soak. A bot walks at random or, with `walk: false`, stands on its spawn; it votes per `vote` (`skip`, `leader`, `random` or a player name) the moment a meeting opens; with `report` it steps toward a body it sees and reports it (a Killer never reports); with `killer` set and `kill` on its own card it hunts the nearest player and strikes once in reach and past the cooldown. `swarm.ts` keeps `code`, `count`, `url` and `ready` (a swarm bot stands still and votes Skip unless asked) so `party.spec.ts` runs unchanged. `soak.ts` starts play through `debug.deal` (one Killer, rotating) and `lobby.start` from the leader bot, restarts after every game over, runs 6 walkers for 30 minutes so bodies, clues and meetings exist, and fails on a presence leak, a dropped bot, a protocol error beyond the 422-428 refusals, a p95 tick above 15 ms, or a run in which no kill or meeting happened. `apps/client/e2e/match.spec.ts` (run with `WDI_E2E_MATCH=1`) plays kill -> report -> vote -> game over -> lobby in two real browsers with standing bots, at 5 and at 4 seats. Bots hold no tasks and no Notebook (M4).

**Quick mode and NPC fill (round 4).** The same brain plays both modes, switching on `state.settings.mode`. In quick mode (GDD 3.11) a bot never moves in the overworld and never takes a portal (the server refuses them 425): at dusk it walks to its own plate (the bakery prop whose `of` is its seat id), holds `onubBalance.timers.plateHoldS` and sends `act.ability {abilityId: 'onub.setPlate', targetId}`; from `nightSleep` until `nightWake` it sends no input; in its window it picks one of the window's alternative acts from `onubBalance.windows`, a target of the kind `acts[id].target` names among the bakery `props` (never its own plate for `otherPlate`, a second near target for `picks: 2`), stands within reach of it, holds `acts[id].holdS` and sends one `act.ability`; at the dawn meeting `claims` posts `meeting.claim {roleId: card.roleId}` once, and the vote is `other` (a random living seat that is not itself, never Skip, chosen automatically in quick mode) with a cap on repeated refusals. `WalkerStats` counts `wakes`, `acts`, `claims` and `nightLeaks`, the last being a presence, a SceneState, a `sceneEnter` without its `nightWake`, or a `nightWake` for another role than the dealt one reaching a sleeper (judged after a short settle time, so a patch trailing `nightSleep` is not a leak). `swarm.ts` exposes `settings` (read-only, from the first bot's state) and `addNpc()`/`removeNpc()` (sent from the first bot, so only a leader's seat is obeyed). `soak.ts --mode onub` lets the leader bot set the mode through `lobby.settings`, skips `debug.deal`, and fails on any night leak or when no window act or no meeting happened; `live.ts --mode onub` plays the role cards into dusk at the bakery. `pnpm bots:soak` and `pnpm bots:soak:onub` run 30 minutes against `apps/server/build`; `.github/workflows/soak.yml` runs both modes (`workflow_dispatch` plus a weekly cron, `timeout-minutes: 45`, never on push).

**Opt-in Playwright suites.** `CI=1 pnpm --filter @wdi/client test:e2e` starts its own server on port 2570 (`WDI_DEBUG=1`) and runs the specs that need no later session; the rest are skipped unless their flag is set, and the orchestrator sets them at integration: `WDI_E2E_MATCH=1` (`match.spec.ts`, the first playable at 5 and 4 seats), `WDI_E2E_ONUB=1` (`onub.spec.ts`, two browsers and three bots through a whole quick match: mode toggle, card line, dusk at the bakery, the loft, a night window, dawn claims without Skip, the vote, the swap log, the lobby), `WDI_E2E_NPC=1` (`npc.spec.ts`: NPC seats added by hand and killed, the fill at Start, and a quick match of one human and three NPCs through the Conductor). The NPC name pool is server-only: no spec imports `@wdi/content/server`, and the specs read names from the lobby list and positions from a standing bot's state. CI runs lint, typecheck and unit tests on every push with a 15 minute limit; the Playwright suites and the soak are not part of it.

### 5.13 V2 migration path

Stays: server, `@wdi/shared`, `@wdi/content`, lobby, CI, hosting. Changes: renderer (Three.js or Babylon.js), input gains `yaw` (field already reserved), `ISceneCollider` gets a capsule-vs-navmesh implementation, `Visibility.ts` gets a cone + occlusion predicate (the policy hook already exists), `zoneId` diverges from `sceneId` for merged volumes. Gate: V2 starts only when V1 rules tests are green and content JSON is frozen behind `schemaVersion`.
