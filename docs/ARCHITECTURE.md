### 5.3 Lobby and join-code flow

Create: `client.create("party", { name, build, deviceId, visibility, invited?, profile? })` (`CreateOptions`; `visibility` is `open` or `private`, open when absent, round 7, GDD 3.21). `onCreate` draws a 5-char code from the unambiguous alphabet, checks uniqueness with `presence.sadd("wdi:codes")`, sets `this.roomId = code`, `setMatchmaking({ private: true })`, `maxClients = 10`. Join: `client.joinById(code.toUpperCase(), opts)` with `JoinOptions` (`profile?` is the device's profile code, copied to `Player.profile` on the public roster). `onAuth` checks `profile` and every `invited` entry (`balance.party.profileCodeLength` characters of the join-code alphabet) and the `invited` count (`balance.party.invitedMax`); any bad value throws the generic join error, as a bad name does. Every joinById failure (missing, locked, full, version mismatch) returns one generic "party not found or unavailable"; specific codes exist only inside a room. Released codes keep a 30-minute presence TTL before reuse. The matchmake route sits behind `trust proxy` with a per-forwarded-IP token bucket (30/min, burst 10) and a global cap (300 joinById/min). **Party list (round 7, GDD 3.21).** The party keeps `visibility` and the `invited` list in room memory, never on the schema, and `syncListing` (in the fixed step, so a join, a leave, a leader pass and `lobby.settings` mode or map are all covered) publishes `visibility, leader, players, max, mode, map, invited` through `setMetadata` when they change; outside the lobby phase it publishes `{}`, so a started room (also `lock()`ed) is never listed and the same party lists again when it returns to the lobby. Matchmaking stays `private: true` for every party. `GET /parties?profile=CODE` (beside `/health`, same CORS rule, `Cache-Control: no-store`) reads `matchMaker.query({ name: 'party' })` in `services/partyListing.ts` and returns `{ parties: PartyListing[] }`: unlocked rooms with metadata, every open one and the private ones whose `invited` holds the profile, newest first, at most `party.listMax`; it copies only the `PartyListing` keys (never `invited`, a seat id, a device id or a role). A bad `profile` answers an empty list; no `profile` lists the open parties. The route takes a token from the matchmake guard's per-IP bucket and from a global bucket of its own (same size as the joinById cap), and answers 429 when either is empty. Start: at least 1 human, phase lobby, leader only; when `players.size` is below `balance.players.min` the room adds NPC seats up to it before dealing, and the leader may add NPC seats up to `players.max` (GDD 3.12). Which seats are NPCs is kept in room memory only (`sim/Npc.ts`, a `Set<string>` that lives as long as the room): an NPC is an ordinary `Player` on the wire, with a session-shaped id (`generateId()`), a name from the server-only NPC name pool (`pickNpcNames`), never the leader; humans are counted by connection, never by the `connected` flag alone (A41). `lobby.addNpc` / `lobby.removeNpc` / `lobby.settings` are leader-only lobby commands consumed in the step; `lobby.settings {map}` takes an id of `MAP_IDS` in either mode (any other value refuses the whole message with `cannot`), writes `Settings.map`, which survives the return to the lobby, and from Start on `sim/MapSites.ts` reads the hub, the start and meeting spawns, the bell, the teaching clue and the map's scenes from that map (GDD 3.13); the room still holds a `SceneState` for every scene id, and views carry only the viewer's own; a human joining a full party takes the newest NPC seat in `onJoin`. Ready is advisory. Kick, transfer and leader handoff ship in M7; a kicked device is banned by `deviceId` + name for that room.

### 5.4 State schema and role secrecy

Schema 5 builder style, no decorators, every Schema under 63 fields, four privacy classes:

```ts
// packages/shared/src/schema/index.ts (excerpt)
export const Presence = schema({ x: t.int16(), y: t.int16(), z: t.int8(), yaw: t.float32(),
  animId: t.uint8(), statusBits: t.uint16(), transitUntilTick: t.uint32() }, "Presence");
export const Private = schema({ role: Role, inventory: Inventory, notebook: t.array(NotebookEntry),
  tasks: t.array(TaskEntry), cabalMates: t.array('string'), cooldownEndTick: t.map('uint32'),
  ledger: t.array(LedgerLine), lensCharges: t.uint8(), myVote: t.string() }, "Private");
export const Player = schema({
  id: t.string(), name: t.string(), traits: Traits, alive: t.boolean(), connected: t.boolean(),
  ready: t.boolean(), hasVoted: t.boolean(), sceneId: t.uint8(),          // Public roster
  presence: t.ref(Presence).view(),                                      // SceneScoped (V1) / Proximity (V1.5)
  priv: t.ref(Private).view(),                                           // Own client only
}, "Player");
export const Door = schema({ id: t.string(), state: t.uint8() /*0 open 1 closed 2 locked 3 broken*/, swingUntilTick: t.uint32() }, "Door");
export const SceneState = schema({ doors: t.map(Door), spots: t.map(Spot), bodies: t.map(Body), clues: t.map(Clue), props: t.map(Prop) }, "SceneState");
export const GameState = schema({ schemaVersion: t.uint8(), phase: t.uint8(), phaseEndsTick: t.uint32(), tick: t.uint32(),
  round: t.uint8(), leaderId: t.string(), settings: Settings, taskBar: t.uint8(),
  players: t.map(Player), scenes: t.map(SceneState).view(), meeting: MeetingState, winner: t.uint8() }, "GameState");
```

`Settings` also carries `npcDifficulty: uint8` (0 easy, 1 normal, 2 hard; GDD 3.12) and `npcSeats: uint8`, how many seats are NPCs, a count that never says which: the marker is the `Set<string>` of `sim/Npc.ts` room memory, written into the match log (`players[].isNpc`) and nowhere else (A41). `onJoin` sets `client.view = new StateView()` and adds the player's own `Player` with its `presence` and `priv` tags and the `SceneState` of its scene. Others are never sent as players: each placed seat walks as an `Avatar` in `SceneState.avatars` (a `.view()` map whose entries `Visibility.ts` adds one by one), keyed by a random 6-byte handle that is re-rolled on every scene entry and every death, and when an impersonation applies or drops, which happens only with no other living seat in the scene, inside a scene entry, or at a Knife strike. An avatar carries the seat whose name, look, scarf and hat glyph it shows (`lookOf`), the height it is drawn at, and the presence fields; its true `seat` is tagged for ghosts only, and a seat aiming its Last Shot receives no avatar. `Player.look` is the public look (GDD 3.17), written for every seat in one tick when the role card closes; `Private.sceneId` replaces the public scene index (there is no public scene index, and no seat's `presence` reaches anyone but its owner, A50). No field marks a cover or an impersonation. Kill and Bandage name a handle that the server resolves to a seat; list acts name a seat. Role, inventory, notebook, cooldowns, cover picks and the handle-to-seat map are therefore never on the wire for other living clients. Every match stream is `sfc32` with four crypto seed words (`sim/seeds.ts`). In V1.5 (dark scenes first, M5b) `Visibility.ts` adds and removes avatars by radius + occluder raycast at 5-10 Hz with a +1 tile hysteresis, so a sprite has history before it is visible. `animId` uses one shared `swing` id for Kill, Crowbar and Check so the animation never discriminates. Fingerprint toucher logs, Blood timers and Case Board intersections stay in room memory. `Player.alive` is public but a kill does not flip it: the server keeps `PlayerSim.dead` in room memory, tells the victim with the private `killed`, and flips `alive` for every dead player when the next meeting opens (or at the ejection), so an unreported kill is known only to its victim and to whoever finds the body (GDD 3.7, A30). A dead viewer's view receives every avatar in its scene, with its true seat; a living viewer's never receives a dead player's. Votes are stored in `priv.myVote`; only `hasVoted` is public; the tally is published in `voteResult`. The meeting phase, board rows and missing list are in `MeetingState` so a reconnecting client rebuilds the UI from state. A fuzz test diffs the state a non-Cabal bot receives over a scripted kill and asserts no field change correlates uniquely with the killer.

**`roleReveal` payload (final, M1).** `{roleId, team: "village"|"cabal"|"neutral", goal, abilities: [{id, name, key, cooldown: number, uses: number | null}], inventory: [{defId, name, qty, tooltip}], cardText, beware, teammates: [{id, name}], traits: {height: "short"|"mid"|"tall", scarf: "red"|"green"|"blue", hat: "cap"|"bowler"|"bare"}}`. Trait values are the ids of `traits.json` (the same order as the public `Player.traits` indices); `teammates` lists the other members of a faction whose `membersKnowEachOther` is true (the Cabal) and is empty for everyone else; `uses` is `usesPerMatch` or null; `cooldown` is seconds, and Kill's is the cooldown of the party size; abilities gated by `minPlayers` above the party size are omitted. The payload is built from `roles.json`, `abilities.json` and `items.json` by `buildRoleReveal` on the server. Round 5 adds four optional main-mode fields: `deck` (the match's deck, card role ids in deck order), `look` (the look this seat walks as), `portrait` (its card portrait key) and, for cover roles only, `coverHints` (GDD 3.17). `docs/PROTOCOL.md` carries the full, generated message tables.

**Start flow (M1).** `lobby.start` is queued like every message and consumed in the room's fixed step (`runLobbyCommands`, `rooms/handlers/lobby.ts`). It creates the match's independent random streams (`sim/seeds.ts`: `sfc32`, four `crypto.randomInt` words per stream, A50), calls `dealMainDeck` (`sim/Deck.ts`: `dealDeck` over `deckFor(n).cards` on the `deal` stream, every Killer card dealt, two cards left undealt) and `dealTraits` on the `traits` stream, writes `priv.role`, `priv.inventory`, `priv.cabalMates` and the public `traits`, locks the room, sets `phase = roleReveal` with `phaseEndsTick` from `balance.json` `phases.roleRevealS`, and sends each client its own `roleReveal`. When every living, connected player is Ready or the card time elapses the phase becomes `grace` (`phases.graceS`) and each client gets `sceneEnter {sceneId: "overworld", spawn, facing}` with its seat's `square_N` spawn (the first overworld spawn if the scene has none). Below `players.min` seats `startMatch` first adds NPC seats up to it (names from the `npcNames` stream of `sim/seeds.ts`), so every deck row is dealt in full; the NPC brain (`runNpcs`, after `syncRoster` and before `applyInputs`, `sim/npc/*`) readies each NPC seat on the role card after an `npc.ready` delay, then runs its routine (stations, strolls, idling, reactions), reports and votes, each NPC seat drawing only from its own keyed streams `npcPlay:<seatId>` and `npcTiming:<seatId>` (GDD 3.12, A41 and A50). Round 6 (GDD 3.19): an auto room (`RoomSim.auto`, set only by `enableAuto` in `sim/auto/Auto.ts`, which fixes `room.fixedSeeds` for every stream and seats the NPCs under given ids) never receives `lobby.start`: the `start` command queued in `autoOf(room).commands` is drained by `runAuto` inside the step, before `runNpcs`, and calls the same `startMatch` with no leader, since `startRefusal` skips the human minimum there. The fixed timestep runs `step` as many times per tick as `sim/auto/clock.ts` `stepsThisTick` says (always one in a `party` room) and records the per-step time.

Error codes: 422 cannot, 423 locked, 424 cooldown, 425 wrong phase, 426 busy, 427 out of range, 428 closed (profile). `docs/PROTOCOL.md` is generated from `@wdi/shared/protocol`.

### 5.6 Movement, actions and netcode

```ts
// apps/server/src/sim/Step.ts — fixed order inside setFixedTimestep(step, 20); PartyRoom drains the lobby
// queue and runs the lobby phase timers right after step() (rooms/handlers/lobby.ts)
export function step(room: PartyRoom, ctx: StepContext) {
  room.state.tick++;
  runDebugStart(room);        // WDI_DEBUG=1 only: a debug.play flag raised in a callback, consumed here
  syncRoster(room);           // one PlayerSim per seat; placeNewPlayers spreads newcomers on square_<n> once the phase is a world phase and sends their one sceneEnter
  applyInputs(room);          // exactly one input per client, newest wins, server-normalised, speed table by sprint/sneak/wounded
  moveAndCollide(room);       // swept AABB vs nav bitmap; 250 ms position ring per player
  runCommands(room);          // queued act.* in arrival order: kill, interact, hold, hide/check, present
  runPortals(room);           // synchronous; sets busy/transit, clears inputs, bumps lastInputSeq
  runAiAndHazards(room);      // sim/Clues.ts runDecay: clue decay and the per-scene cap (M3); wolves (M5)
  if (room.state.tick % 4 === 0 || sim.viewsDirty) reconcileViews(room);   // Visibility.ts at 5 Hz, at once after a crossing or placement
  runPhases(room);            // sim/Phases.ts: phase timers, meeting requests, deaths -> checkWin, game over (M3)
}
```

Every C->S action is queued and consumed inside `step()`; nothing mutates state in a message callback. Players have a `busy` state (dying, transit, hidden, channelling) during which actions on or by them are rejected with 426. Kills resolve on the validated tick (the 1 s animation is cosmetic) with range slack of `range + maxSpeed * 0.25 s` against the position ring, same scene, alive, not hidden, not bandaged, and a nav raycast. Held actions are start/stop commands re-validated every tick. `Presence.animId` is `interact` while the seat's own `act.hold` runs, `walk` only on a tick its position actually changed, else `idle` (`publishPresence`). `patchRate` 50 ms; the client lerps remote players with a 150 ms delay and teleports a sprite on view add. No client prediction in V1 (lerp only; the local player moves on server echo with input-rate smoothing). Positions are `int16` pixels, enums `uint8`, time is the tick counter. The swarm bot publishes tick-time and patch-size histograms through `/health`; M4 is gated on p95 tick < 15 ms with 10 bots and 3 wolves.

**M2 implementation notes (Session G).** These are implementation constants, not rules; they live in `apps/server/src/sim/constants.ts` and `packages/shared/src/nav` and are listed here until the owner moves any of them into `balance.json`: the collision box is a 0.5-tile square under the feet (`FOOT_HALF_PX` 16); a client whose input goes quiet stops after 5 ticks; a door is usable from 1.5 tiles (`PORTAL_REACH_TILES`, the same reach as the other verbs); the ring holds 250 ms (6 samples). Speeds, the 0.6 s transit, the 3 s swing and door noise come from `balance.json`. `input.move` keeps only the newest message per client in the queue; `act.enterPortal` is queued by `runCommands` and consumed by `runPortals` (errors come back as the `error` message, success as `sceneEnter`, not as a request/response). `Player.presence` and `Player.priv` carry their own view tags (1 and 2) so a client can be granted another player's `presence` without receiving even an empty `priv`; `Visibility.ts` adds and removes that tag as players enter and leave a client's scene. Presence is encoded to other clients only in world phases (grace, day, dusk, night, dawn, immunity, final night). The first placement in a world phase puts every player on `square_<n>`, sets `alive`, fixes the scene profile from the party size and sends `sceneEnter`. `WDI_DEBUG=1` adds `debug.play`, which moves a lobby to grace for the bot soak and the tests.

**M3 implementation notes (Session L).** `runCommands` dispatches `act.ability`, `act.hold`, `act.reportBody` and `act.bell` to `sim/Actions.ts` (Kill in `Kill.ts`, Collect in `Hold.ts`) and ends by running `runHolds`, so every hold is re-validated each tick. `validateKill` and `segmentBlocked` (pure, `packages/shared/src/rules/kill.ts`) decide a strike; the room only reads state, calls them and writes the result. "Alive" in a verb always means `!PlayerSim.dead`. Clue memory (decay tick, spawn order, collectors) lives in `RoomSim.clueMeta`; the schema carries only what a client may read. `runDecay` (Clues.ts) expires Footprints; the per-scene cap is applied at each spawn. Ghosts skip collision (they stop at the scene edge), skip the busy and lock checks of portals, swing no door and emit no noise; a ghost's crossing moves only `PlayerSim.sceneIdx`. `emitNoise` lives in `sim/Noise.ts`.

### 5.7 Scene sync

`act.enterPortal` validates distance, lock state, profile and phase, sets `sceneId`, position and the 0.6 s transit, swaps `scenes` view entries and other players' `presence`, and broadcasts a door `swing` plus a noise event. The client `World` scene restarts with the new `sceneId` and loads only that scene's manifest. Meetings run the same transition path for every player (busy, input clear, `sceneEnter` to a spread spawn). After a meeting everyone stays at the square; hiding spots are emptied; bodies stay. Ghosts bypass portal checks and get an all-scenes view flag.

**M3 meeting flow (Session K, A31).** `runPhases` (`sim/Phases.ts`, last in the step) owns the phase clock, the drain of `sim.deaths` and `sim.meetingRequests`, and the debug helpers; `sim/Meeting.ts` opens the meeting, takes votes and runs the reveal; `sim/Win.ts` evaluates `checkWin`, ends the match and returns the room to the lobby; `sim/Chat.ts` routes chat by channel; `sim/Flow.ts` holds `setPhase` and the room-memory flow state. A meeting places every player on the square without a `sceneEnter` and sends `meetingStart` afterwards; immunity places them again with an announced `sceneEnter`, which is the client's cue to leave the meeting. A living viewer's reconcile skips ghosts (`PlayerSim.dead`); in the meeting, reveal and game-over phases `isWorldPhase` is false and no presence is encoded.

### 5.8 Rules engine

`packages/shared/src/rules`: pure functions with seeded PRNGs (`mulberry32`, and `sfc32` for the match streams of `sim/seeds.ts` since round 5) and tick-based time: `dealDeck(ids, cards, alwaysDealt, rng)` deals the public deck (`roles.json` `decks[String(n)].cards`); `dealTraits`; `validateKill(actor, target, scene, tick)`; `generateClues(kill, sceneGraph, rng)` (2 of 3 traits, print, Blood, smear); `resolveVotes(votes, alive, suspectSet, consecutiveNoEject)`; `intersectSuspects(verified, living)`; `checkWin(state)` (parity with Thief/Drifter exceptions, practice rule, tasks, Final Night); `rollCall(state)`. Property tests cover every deck row (every Killer dealt, two cards undealt, seed reproducibility). The room only orchestrates: read state, call rule, write state. (M3: `resolveVotes(votes, living, options)` and `checkWin(livingFactions, rule)` are the two shipped signatures; the anti-stall rules are options that default off and the suspect set, the practice-rule exceptions and the Final Night arrive with M4.)

### 5.9 Client

Scenes: `Boot` (flags, `/health` poll) -> `Preload` -> `Landing` (DOM) -> `Lobby` (DOM) -> `RoleReveal` (DOM, CSS flip) -> `World` (restart per `sceneId`, camera follow with bounds and 0.1 lerp) -> `Meeting` (launched over a sleeping `World`) -> `GameOver`. HUD, inventory, notebook, chat, board and touch controls are a DOM overlay with `pointer-events: none` except on controls; Phaser draws world prompts and nameplates. `NetworkService` wraps `@colyseus/sdk` with `Callbacks.get(room)`, typed `send` / `request`, a `mitt` bus, and the reconnection token in `localStorage` keyed by room code (cleared on consented leave or game over). `EntityView` maps players and scene entities to sprites; `PlayerView` composes body + scarf + hat + blood overlays and picks `char/<body>/<anim>/<dir>` keys; a shared `dirFromVector(dx, dy)` in `@wdi/shared` with a unit test is the only direction table. Input is timer-driven at 20 Hz, decoupled from rAF, coalesced after `visibilitychange`. The view is isometric (round 5, SPRITES 10): the server, the wire and every rule stay in the world frame, and the client alone projects with `@wdi/shared/iso` (`PlayerView`, `BodyView`, `ClueView` and `PropView` take world px and place themselves; input turns screen keys and the touch stick into world vectors before they are sent).

Scene flow (round 3): `NetworkService.room` (getter, plus a `room` bus event, `null` once the room is gone) is what `net/worldRouter.ts` attaches its two feeds from, `ColyseusWorldFeed` and `ColyseusMeetingFeed` (`net/meeting.ts` is the contract: public roster, `MeetingState`, the clock, own vote, chat lines, the `meetingStart`, `voteResult`, `gameOver`, `chat.msg` and `phaseChange` events, `vote(target)` and `say(text)`). The world feed registers the room's `sceneEnter` once and the router re-emits it on `net.bus` for `RoleReveal`. The router is the only code that starts, sleeps or stops `World`, `Meeting` and `GameOver`: a `sceneEnter` while no meeting is open restarts `World`; `meetingStart` sleeps `World` and starts `Meeting`; only a `sceneEnter` that arrives after `meetingStart` stops `Meeting` and starts `World`; `gameOver` stops both and starts `GameOver`; a `phaseChange` back to the lobby starts `Lobby`. `?mock=1` has the same shape: `MockNetwork.openMeeting` runs a `MockMeetingFeed` (`net/mock/meetingMock.ts`) when the mock world sends `meetingRequest`, then calls the world feed's `resume()` or ends the match.

### 5.11 Security

Every action validated server-side (range, phase, cooldown, ownership, alive, busy). `maxMessagesPerSecond = 100` as a hard cap; per-type token buckets drop rather than disconnect; disconnect only after 3 overflows in 10 s. Names 2-16 characters, server-side profanity list (M7). Chat channels derived from alive status and role; the client's channel field is ignored. Debug handlers register only with `WDI_DEBUG=1` and never in production; a CI test asserts `debug.roles` is absent from a production build. Seeds sent to clients drive cosmetics only. `onLeave` during play spawns a "vanished" body; in lobby it frees the seat.

**Admin gate (round 6, ROADMAP M5d; `docs/round6/auto-admin.md` 6 to 8).** The owner's god view of an all-NPC match is a second Colyseus room, `admin`, and two Express routes. Everything is off unless `WDI_ADMIN=1` and every other `WDI_ADMIN_*` variable is set (`adminConfig()` in `services/adminAuth.ts` is null otherwise, and `server.ts` then registers neither the room nor the routes, so an `admin` create fails with the same generic join error as any room that does not exist). There is no password and no cookie anywhere in the gate: GitHub says who the browser is and an allowlist of logins decides.

| Variable | Meaning |
|---|---|
| `WDI_ADMIN` | `1` turns the whole thing on; anything else leaves it off |
| `WDI_ADMIN_GITHUB_CLIENT_ID`, `WDI_ADMIN_GITHUB_CLIENT_SECRET` | the owner's GitHub OAuth app, whose callback URL is `https://<server host>/auth/github/callback` |
| `WDI_ADMIN_GITHUB_LOGINS` | comma-separated GitHub logins allowed in, compared lower-case |
| `WDI_ADMIN_SECRET` | the HMAC key of the OAuth state and the token: 32 random bytes in base64 from `openssl rand -base64 32`, generated on the owner's machine; fewer than 32 characters leaves the gate off |
| `WDI_ADMIN_CLIENT_URL` | where the callback sends the browser, an http(s) URL (`https://groot99-droid.github.io/Who-Did-It/`) |

The values live in the host's settings (Railway variables) and never in a file of either repo, a pull request or a log. **Flow:** `GET /auth/github/login` redirects to GitHub (`scope=read:user`) with a stateless `state` (a nonce and the issue time under the key); `GET /auth/github/callback` verifies the state (HMAC compared with `timingSafeEqual`, at most 10 minutes old), exchanges the code, reads the user's login, checks the allowlist and redirects to `${WDI_ADMIN_CLIENT_URL}#/admin?token=...`; the client moves the token to `sessionStorage['wdi:adminToken']` and scrubs the hash. The token is `base64url(claims).HMAC` with `sub` (the login), `id` and `exp`, and lives `TOKEN_TTL_S` (3600 s; an ops constant, not a game number). The state and the token are signed under different purposes, so neither verifies as the other, and `verifyAdminToken` checks the allowlist again, so removing a login from the variable locks it out within the token's life. Every failure of the callback answers one `403 forbidden`, the callback is rate limited as a whole (20 burst, 20 a minute) before it spends the two GitHub calls, and no response says which check failed.

**The room.** `AdminRoom extends PartyRoom`; its static `onAuth` runs for create and every join and checks the build and the token from the join options (`{ build, token }`), throwing the generic join error for anything else. It enables the auto match (`enableAuto`, the defaults from `balance.json` and `DEFAULT_MAP`), registers the `admin.*` handlers and the bus feed, and admits one client: no seat, no `Player`, `client.view = createAdminView(room)`. The view holds every `Player` with the `presence` and `priv` tags and every avatar with the `ghost` tag (so each avatar carries its seat); `reconcileViews` hands the admin client to `reconcileAdminView` before its own work (the one locked line in `Visibility.ts`), so a `party` room, which never marks an admin client, is untouched. A second client is refused; a leave or a drop disposes the room (the page opens a new one). A `party` room's message gate accepts only the `C2S` union, so an `admin.*` message to it is dropped.

**The handlers** (`rooms/handlers/admin.ts`) validate the payload and push an `AutoCommand` (`setup`, `start`, `reset`, `clock`) onto `autoOf(room).commands`; `runAuto` applies them inside the step (at most 32 wait at once). Two details of a room that can be paused: a paused room runs no step and so would never drain its queue, so before each tick the admin room asks for one single step whenever commands are waiting; and `admin.clock {step}` adds to the clock's single-step counter directly (a loop-control counter the tick loop consumes, not game state), capped at 100 per message, so a step is exactly one tick. After every tick the room sends the admin client `admin.snapshot` (the tick, phase, clock, every seat with role, cover and NPC brain, the mobs and the invariant failures kept since Reset), `admin.event` for the tick's bus events and `admin.invariant` once for each new failure of the registered invariants, which run about once a second of sim time. The fields are in `docs/PROTOCOL.md` "Admin (WDI_ADMIN only)".

**Tests.** `adminAuth.test.ts`: the config gate, the token and state round trips and their refusals, the routes against a fake GitHub, the uniform 403, the flood, and a server booted without the variables (no room, no routes). `adminRoom.test.ts`: every bad token gets the generic error, a good token joins with no seat and sees every role and every avatar's seat, a second client is refused, the room is disposed on leave, and a `party` client of the same server receives neither `Avatar.seat` alive nor any `admin.*` message and cannot change its clock; the wire tests cover the snapshot every tick, setup, start, reset, the speed, pause, the exact single step, Start while paused and the invariant rows.
